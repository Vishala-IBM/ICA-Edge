# Agent Capability Matrix

This matrix consolidates the 19 agent skills with the agent READMEs, sample-data dictionaries, master-data documentation, `enterprise_process_model.md`, `Agent_Interaction_Model.md`, and `sap_reference_architecture.md`.

**Dependency direction:** Upstream agents provide information or approvals this agent consumes; downstream agents consume this agent's outputs. `H-##` refers to the cross-agent handoff registry in `enterprise_process_model.md`; `AIM` refers to the explicit contracts in `Agent_Interaction_Model.md`. `Coordination` identifies a README/skill relationship without a formal handoff contract. A listed relationship is not by itself proof of a deployed interface.

**Data object terms:** Master data objects are governed identities, reference data, or hierarchies. Transactional data objects are events, plans, balances, measurements, or records created through business processes. Names reflect the repository's synthetic datasets and the conceptual SAP process model; confirm production schemas and SAP release specifics before implementation.

## Interpretation Notes

- The enterprise process model supplies primary process ownership and most formal handoffs. The Agent Interaction Model separately confirms Demand Planning -> Supply Planning, Procurement -> Supply Planning, and Asset Reliability -> Supply Planning; those contracts are included even where the process handoff registry has different coverage.
- The dependency cells combine formal handoffs with README/skill interactions. Entries marked `Coordination` are documented relationships, but their direction, payload, cadence, and interface are not formalized in the shared contract model.
- KPI names and formulas are proposed operational definitions unless explicitly stated in the shared KPI model or sample-data dictionaries. The enterprise KPI model's numeric targets are illustrative; validate definitions and targets with process owners.
- ECC table/object references and S/4HANA modules in individual skills are architectural reference mappings, not a confirmed customer system inventory. Validate availability, release, licensing, customizations, and released API/CDS equivalents.
- Master-data documentation identifies unresolved gaps including Material, Counterparty, Commodity/Benchmark, Carrier, Ship-To, Cost Center/GL linkage, and several incomplete joins. Rows intentionally retain these as needed entities rather than implying current conformed masters exist.
