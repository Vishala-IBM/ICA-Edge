# Dashboard Dataset Implementation

**Implementation Readiness:** Conditional. The build plan defines logical datasets and rules, but sources are synthetic/proposed and production feeds, complete dictionaries, KPI approvals and refresh SLAs are not established. Implement versioned read-only datasets first; unavailable measures must remain unavailable, not zero.

| Dataset | Source | Refresh Schedule | Transformations | KPI Mapping | Validation Rules |
|---|---|---|---|---|---|
| **Conformed Dimensions**: Period, Product, Material (distinct), Customer, Region, Plant, Business Unit, Source/Version | Approved master/reference snapshots and source metadata. | Per approved snapshot; cadence owner-defined. | Standardize canonical keys; apply only explicit, effective-dated crosswalks; retain source/version and mapping status. | Shared filter/join dimensions for all dashboard KPIs. | Unique canonical keys; effective period and version present; no inferred Product/Material or Region/Plant equivalence. |
| **FactDemandForecast**: forecast/version, scenario, Period, Product, optional Customer/Region, quantity/UoM, method, approval, provenance; actuals optional | Versioned forecast output; `demand_forecast.csv`, `demand_scenarios.csv`, `sales_forecast.csv`. | Per approved forecast version/planning cycle. | Align only compatible grain/period/UoM; aggregate by scenario/version; compute accuracy only with aligned actuals and approved formulas. | Forecast MAPE/bias and demand side of Demand-Supply Gap. | Require dictionary/schema, explicit scenario semantics, valid key/period/UoM and source freshness; no accuracy metric without actuals. |
